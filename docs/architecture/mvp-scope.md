# 第一版 MVP 范围

## 目标

第一版只证明一件事：

> 能够使用 C++ 将一张物流园地图从生产草稿变成正式版本和车端地图包，并支持后续地图更新。

核心闭环：

```text
物流园 V0
→ C++ 解析和质检
→ MapVersion V1
→ C++ 编译器
→ MapPackage V1
→ C++ Vehicle Map SDK
→ Candidate Patch
→ MapVersion V2
→ 临时封路后重新规划
```

## 必须完成

- C++20、CMake和自动化测试工程；
- Canonical Map Model；
- 一张8～12条车道的物流园教学地图；
- 几何、引用、拓扑和可达性质检；
- 不可变的MapVersion V1；
- C++地图编译器和MapPackage V1；
- C++车端加载、附近查询、拓扑查询和路径规划；
- 简单Web地图工作台，核心逻辑仍由C++实现；
- Candidate Patch审核并发布V2；
- 临时封路事件覆盖和车端重新规划；
- 一个复用相同核心能力的简化矿区示例。

## 暂不实现

- 真实SLAM、点云处理和感知算法；
- 局部轨迹规划、车辆控制和障碍物避让；
- 生产级多车融合建图；
- 完整OpenDRIVE、Lanelet2或NDS标准实现；
- 多人实时协同编辑和复杂审批；
- 微服务、Kubernetes和量产级OTA；
- 增量二进制地图包；
- 量产车辆功能安全认证。

## 完成标准

第一版完成时必须能够现场演示：

1. 读取物流园V0并输出质检报告；
2. 质检通过后发布MapVersion V1；
3. 将V1编译成MapPackage V1并反向验证；
4. C++ SDK加载地图包并规划仓库到月台的路线；
5. 审核一个Candidate Patch并生成V2；
6. 不更新地图包，仅通过临时封路事件触发车端重新规划。

该MVP是教学和求职作品，不可直接用于量产车辆。
